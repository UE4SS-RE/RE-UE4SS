# 修复缺失的 AOB（进阶与深入）

当 UE4SS 因缺失 AOB（字节数组特征码）而无法正常启动时，你可以用 Lua 提供自定义 AOB 与回调函数。
不过，这样做需要一定的逆向工程知识与工具环境，起初可能显得复杂。
本指南在原有说明的基础上进行扩展，提供更多细节、背景与技巧。

## 前提条件

- **掌握基础逆向工程概念：**
  你应当大致了解什么是特征码（AOB）、如何使用调试器，以及如何在 x64dbg 中浏览内存。

- **熟悉 UE4SS 的配置与目录：**
  请确保你清楚 `UE4SS_Signatures` 文件夹应该创建在哪里（它应位于 `ue4ss.dll` 旁边，或位于特定游戏的工作目录中）。

- **准备并安装工具：**
  - **Epic Games Launcher 与 Unreal Engine：** 用于创建与目标游戏引擎版本一致的"空 Shipping 游戏"环境。
  - **x64dbg：** Windows 上的调试器工具（https://x64dbg.com/）。
  - **（可选）Baymax Tools：** 便于生成特征码的插件。
  - **（可选）Swiss Army Knife（由 Nukem9 开发）：** 便于提取带正确通配符的特征码。

## 何时需要这样做，以及原因

有些游戏没有使用虚幻引擎的默认配置，而我们只开箱支持默认配置。
任何影响编译器生成代码的因素（包括开发者使用 Clang 而非 MSVC）都可能让我们内置的 AOB 失效。
这些 AOB 用于查找 UE4SS 正常工作所必需的关键函数与变量。

## 整体概览

1. **确定缺失了哪些特征码：** 找出 UE4SS 找不到的函数或变量（例如 GUObjectArray、GMalloc、FName）。
2. **搭建参考环境：** 使用与你游戏相同的虚幻引擎版本，创建一个带调试文件（PDB）的空虚幻引擎游戏（Shipping 目标）。该环境可帮助你清晰地定位函数特征码。
3. **逆向并提取 AOB：** 使用 x64dbg（以及可选插件）打开空项目，在内存中定位目标函数，复制构成可靠特征码的唯一字节。该特征码应当正确设置通配符，否则在你的游戏中可能找不到。
4. **把特征码应用到实际游戏：** 用 x64dbg 附加到目标游戏，找到匹配的字节，确认你提取的特征码与要修改的游戏中的代码一致。
5. **编写 Lua 脚本：** 在 `UE4SS_Signatures` 中写一个 Lua 文件，告诉 UE4SS 要搜索什么 AOB 模式（通过 `Register`）以及最终返回什么地址（通过 `OnMatchFound`）。

## 查找 AOB：更详细的说明

> [!CAUTION]
> 逆向这些特征码并不简单。你可能需要跳出本指南的范围，阅读逆向工程教程，或向社区求助。以下步骤只是起点，而非完整的逆向工程指南。

### 第 1 步：确定游戏的虚幻引擎版本

UE4SS 会尝试自动检测引擎版本。若你需要确认，以下步骤通常有效：

- 右键点击游戏的 `.exe` 文件（通常位于 `Binaries` 文件夹中）。
- 选择 **属性** -> **详细信息** 标签页。
- 查看"文件版本"或"产品版本"字段，它通常与虚幻引擎版本相关。

例如：若显示 `5.3.2.0`，它很可能对应 UE 5.3.2。
少数情况下，该版本号可能为空，或者指向游戏版本而非引擎版本。
注意最后一位数字通常不重要，因此如果你的游戏使用 UE 5.3.2，你的空项目一般可以使用任意 5.3 版本。

### 第 2 步：安装匹配的虚幻引擎版本

- 创建 [Epic Games](https://www.epicgames.com/) 账号并安装 **Epic Games Launcher**。
- 在启动器中进入 **Unreal Engine** -> **库** 标签页，安装与游戏版本匹配的引擎版本（例如 UE 5.3.2）。

### 第 3 步：创建带 PDB 的空 Shipping 游戏

1. 启动已安装的虚幻引擎版本。
2. 在新建项目窗口中，选择 **游戏** 标签页 -> **Blank** 模板。
   - 取消勾选 "Starter Content"，因为它并不需要，取消勾选可以节省时间与空间。
   - 为项目命名并指定目录。
3. 创建完成后，打开 **平台** -> **打包设置**，启用 "Include Debug Files in Shipping Builds"。
4. 在 **平台** -> **Windows** 中，选择 "Shipping" 配置（或与你目标游戏的构建类型一致的其他配置）。
5. **打包项目** -> 选择一个文件夹。
6. 打包完成后，确认输出文件夹的 `Binaries` 目录中同时包含 `.exe` 与 `.pdb`。`.pdb` 文件提供用于逆向的符号信息。

### 第 4 步：使用 x64dbg 分析空项目

1. 从 [https://x64dbg.com/](https://x64dbg.com/) 安装 x64dbg。
2. 从根目录运行你刚打包的空项目 `.exe`。
3. 打开 x64dbg。
   - 进入 **文件** -> **附加** -> 选择空项目的 `.exe`。
   - 确保你附加的是位于 `Binaries` 或根目录下的 shipping `.exe`（以能成功附加为准）。

### 第 5 步：定位目标函数

你需要知道要在目标游戏中匹配哪个函数或变量。例如，如果 UE4SS 在 `GMalloc` 上失败，你必须先找到 `FMemory::Free` 作为定位 `GMalloc` 的参照。

**可选步骤：**

- 将 Epic Games 账号与 GitHub 关联以访问虚幻引擎源码。
  - **Epic Games 网站** -> **管理账号** -> **应用与账号** -> **GitHub**
  - 通过邮件接受邀请。
- 浏览虚幻引擎源码以找到你需要的函数。对于 UE5.3.2 中的 `FMemory::Free`，你可以查看：
  [UE 源码中的 FMemory::Free](https://github.com/EpicGames/UnrealEngine/blob/5.3.2-release/Engine/Source/Runtime/Core/Public/HAL/FMemory.inl#L142)

### 第 6 步：在 x64dbg 中定位函数

注意 x64dbg 存在一个 bug：从符号标签页跳转到代码或内存有时不能正常工作。
如果你跳转后没有看到预期内容，重启 x64dbg 再试一次是值得的。
你也可以从符号标签页复制地址，然后在 CPU 标签页的正确面板中手动跳转。

1. 在 x64dbg 中切换到 **符号** 标签页。
2. 在左窗格中选择该 `.exe`。
3. 在右窗格中搜索函数名（例如 `FMemory::Free`）。
4. 双击找到的函数，跳回 CPU 视图，指令指针会定位到内存中该函数的起始处。

### 第 7 步：提取特征码

确定函数起始位置后，你需要复制一段唯一的字节序列：

1. 可以考虑安装 [Baymax Tools](https://github.com/sicaril/BaymaxTools) 或适用于 x64dbg 的 Swiss Army Knife，以简化特征码提取。
2. 在函数开头选中一组指令。
   - 右键 -> **复制** -> **选中内容（仅字节）** 以获取原始字节序列。
   - 使用 Baymax Tools：右键 -> **Baymax Tools** -> **复制特征码** 以获取现成的特征码模式。
3. 保存这些字节或模式以便后续对比。你或许想把它们存到文件中，方便随时回查。

### 术语说明

- **特征码（Signature）：** 经过精心挑选的字节序列，用于唯一标识某个函数或代码片段。
- **字节块（Block of Bytes）：** 一段简单、可能无结构的原始数据，本身并不唯一。
- **RIP（指令指针）：** 保存下一条要执行指令地址的 CPU 寄存器。

### 第 8 步：在实际目标游戏中搜索

有了参考特征码之后，需要在目标游戏中找到它：

1. 启动目标游戏的 `.exe`。
2. 像之前一样附加 x64dbg：**文件** -> **附加** -> 选择游戏的 `.exe`。
3. 在 x64dbg 中搜索你从空项目提取的特征码。
   - 若直接搜索失败，可以尝试部分字节序列。
   - 尝试 Baymax Tools 生成的模式。
   - 对比空项目与实际游戏之间的指令，定位相似的代码区域。

如果找到匹配项，你就找到了实际游戏中与目标函数或变量对应的地址。
如果找不到，你可能需要优化特征码、换用函数中的其他位置，或向社区求助（UE4SS Discord 或 GitHub Issues）。

### 第 9 步：在 UE4SS 中应用特征码

有了可用的 AOB 之后：

1. 在工作目录中创建 `UE4SS_Signatures` 目录（如果尚不存在）。
2. 为缺失的 AOB 创建对应的 `.lua` 文件（例如修复 GMalloc 就创建 `GMalloc.lua`）。
3. 在该 `.lua` 文件中定义 `Register` 与 `OnMatchFound` 函数。

**Register 函数：** 以字符串形式返回你的 AOB 特征码（空格可选），例如：

```lua
function Register()
    return "48 8B D9 48 8B 0D ?? ?? ?? ?? 48 85 C9 75 0C E8 ?? ?? ?? ??"
end
```

**OnMatchFound 函数：** 接收匹配地址，必须返回目标函数或变量的确切内存地址。必要时可使用 `DerefToInt32` 解析相对地址。

```lua
function OnMatchFound(MatchAddress)
    local MovInstr = MatchAddress + 0x03
    local Offset = DerefToInt32(MovInstr + 0x3)
    local RIP = MovInstr + 0x7
    local GMallocAddress = RIP + Offset
    return GMallocAddress
end
```

### 验证你的工作

- 再次带 UE4SS 运行游戏。若成功，UE4SS 现在会使用你的自定义脚本找到之前缺失的地址。
- 若静默失败，请确认：
  - Lua 脚本位于正确的目录中。
  - 你的 AOB 正确且唯一。
  - `OnMatchFound` 返回了正确的最终地址。

如果仍然卡住，可以考虑把详细步骤、日志与代码片段发到 UE4SS 社区渠道。
你提供的细节越多，别人越有可能帮你找到解决方案。

## 技巧与故障排查

- **耐心与迭代：** 提取与优化 AOB 常常是试错的过程。若某个特征码不生效，换一段字节序列，或在函数中换个位置查找。
- **部分特征码：** 若完整函数特征码找不到，可以尝试其中唯一的部分。
- **社区帮助：** 若卡住，可在 UE4SS Discord 或 GitHub Issues 中展示你的步骤、脚本与日志。
- **仔细检查偏移：** 差一或索引错误是常见问题，请再次核对你的计算。
- **手动验证：** 有时在 x64dbg 中再次运行空项目并与目标游戏内存对比，能凸显出差异。

按照这些扩展步骤并利用所提供的工具，你会对如何用 UE4SS 修复缺失 AOB 有更全面的理解。
尽管仍然复杂，这份扩展指南应当有助于理清流程，并为逆向工程领域提供实用见解。
